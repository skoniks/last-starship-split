# Last Starship — Перевод и рефакторинг

## Проект

Рабочая среда для работы с русским переводом UI-строк игры Last Starship.
Каждая строка имеет колонку `translation`:

- **`translation` пустая** → строка **не переведена** → её **переводим** с английского.
- **`translation` заполнена** → строка **уже переведена** → её **рефакторим** (улучшаем читаемость).

Одна и та же сессия может содержать и то, и другое. Определяем по строке, а не по файлу.

## Файлы

| Путь | Роль |
|---|---|
| `language.csv` | Исходный файл: `state,key,svn,english,translation` |
| `language/*.csv` | Разбитые по модулям: `key \| original \| translation` |
| `original/original.csv` | Эталон для сравнения |
| `original/language.csv` | Дифф изменений |
| `glossary.csv` | Словарь терминов (колонки `en,ru`) |

## Рабочий цикл

1. `npm run index` → получить разбитые файлы в `language/`
2. **Refactorer** обрабатывает строки: переводит пустые, рефакторит заполненные
3. **Reviewer** проверяет дифф по чек-листу
5. `npm run build` → собрать обратно в `language.csv`
6. `npm run export` → дифф против эталона

## АГЕНТ 1: REFACTORER

### Задача
Для каждой строки:
- если `translation` **пустая** — **перевести** с английского (`english`);
- если `translation` **заполнена** — **улучшить читаемость** (рефакторинг), не меняя смысл.

### Что редактировать
- **ДА:** диалоги, нарративные тексты, сюжетные описания, инструкции игроку
- **НЕТ:** названия предметов, UI-метки, подсказки, технические строки (не переписывать)

### Правила (общие для перевода и рефакторинга)

**Сохранять без изменений:**
- Ключ и оригинал — не трогать
- Термины из `glossary.csv` — не заменять, не менять регистр (склонять можно)
- Двойные пробелы, переносы строк
- HTML-теги (содержимое тегов — перевести, если не переведено)
- Маркеры: `*X`, `S*X`, `$*X`, `L*X`, `R*X`
- Клавиши: `{ToggleMap}`, `{TranslatorWindow}` и т.п.

**Запрещено:**
- Добавлять «ё» (использовать «е»)
- Добавлять спецсимволы (длинное тире, точку с запятой и т.п.)
- Удалять двойные пробелы между предложениями
- Удалять точки в конце предложений

**Разрешено (только при рефакторинге):**
- Переставлять слова для естественности
- Склонять термины (но не заменять)
- Упрощать сложные конструкции **внутри одного предложения**
- Убирать тавтологию **внутри одного предложения**

**Критерий «готово»:**
Если перевод уже естественный, грамматически корректный и термины совпадают
со словарём — **не менять** и переходить к следующей строке.
Не искать, что ещё можно «улучшить».

**Если не уверен** — не менять, пометить строку и спросить.

### Особые правила
- Обращение к игроку: «вы/вас/ваш» (не «ты/тебя/твой»)
- STEAM CLOUD → ОБЛАКО STEAM
- STEAM WORKSHOP → МАСТЕРСКАЯ STEAM
- STARGATE → ЗВЕЗДНЫЕ ВРАТА (как объект/название)
- GREEN TEAM / RED TEAM (арена) → команды игроков, не экипаж
- Crew → Экипаж, Team → Команда
- Black Box Flight Recorder → Бортовой Самописец
- Power Grid → Энергосеть (не Электросеть)
- MW → МВт, MJ → МДж

### Формат вывода
Тот же формат: `key | original | translation`
Изменения только в третьей колонке.

## АГЕНТ 2: REVIEWER

### Задача
Проверить **дифф** (before → after) по чек-листу. Не предлагать альтернативы —
только находить нарушения.

### Чек-лист (проверить каждую изменённую строку)

- [ ] Ключ не изменён
- [ ] Оригинал не изменён
- [ ] Термины из `glossary.csv` сохранены (слово + регистр)
- [ ] Не добавлены знаки препинания
- [ ] Не удалены знаки препинания
- [ ] Не заменены знаки препинания
- [ ] Нет буквы «ё»
- [ ] Двойные пробелы сохранены
- [ ] HTML-теги, маркеры, клавиши не сломаны
- [ ] Предложения не объединены и не разделены
- [ ] Изменён только текст (диалог/нарратив), не UI-метка
- [ ] Грамматика корректна (нет сломанных конструкций)

### Формат вывода
```
OK — нарушений не найдено
```
или
```
Нарушения:
- строка 12 (hud_cabins): удалена точка в конце предложения
- строка 27 (settings_analytics): термин «Аналитика» → «Статистика» (в глоссарии: «Отправка Статистики»)
```

### Что НЕ делать
- Не переписывать текст
- Не предлагать «лучший» вариант
- Не оценивать стиль
- Только чек-лист, да/нет
